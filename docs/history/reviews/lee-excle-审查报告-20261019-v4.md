## 三、遗留与新发现

### P1-新：压缩的兜底正则已对不上新文案

**位置**：`web/src/services/compaction.ts:110`

```ts
const verifiedRegex = /(?:区域\s*([A-Z]+\d+:[A-Z]+\d+)\s*验证通过|宏【([^】]+)】已运行完成)/gi;
```

新证据文案为"**抽样核验一致**"，该正则只认"验证通过"。
后果：结构化元数据缺失时（历史消息、外部构造消息），兜底提取**永远匹配不到**，证据静默消失且无告警。

**建议**：正则改为 `(?:验证通过|抽样核验一致)`，或删除兜底、仅认结构化元数据（缺失即视为无证据，更诚实）。

### P2：`verified` 仍是不可达成员

`llm.ts` 联合类型保留 `verified`，但无任何路径产出。本轮选择"让分支可达"而非"删除状态"。
功能无害，但类型在说谎——读者会误以为系统能给出比 `matched` 更强的保证。

### P2：C# 侧测试为源码字符串断言

`test_suite_unit.cjs:6505` 读取 `FormulaAuditService.cs` 源码文本，断言其包含"全簿概览、递归探测、循环引用防御"等字样。
这是**契约存在性检查**，非行为测试。项目标注为"静态核验"，措辞诚实，但证明不了运行时正确性。

### P2：零依赖兜底转译器未被验证

三级降级最后一级用正则剥 TS 类型注解（`:\s*([A-Za-z0-9_<>\[\]|&\s'"]+)(?=[=,)])`），在泛型、箭头函数、对象字面量上易切错。
该路径仅在 vite 与 esbuild 均缺失时触发，**等同于一条从未被执行过的代码**。
