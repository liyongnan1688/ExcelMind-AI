# ExcelMind AI 产品迭代主规划路线图 (Product Roadmap)

> **文档属性**：项目唯一主规划与迭代演进基准 (Single Source of Truth)  
> **生效日期**：2026-10-02  
> **基准版本**：v1.2.0 (Git Commit: `231ae3a`)  
> **产品定位**：Windows 桌面 Excel 的中文 AI 与可复用 VBA 自动化工作台。  
> **宿主架构**：Excel-DNA (.NET Framework 4.8 / C#) + Microsoft Edge WebView2 (Svelte 5 SPA)。  

---

## 1. 核心愿景与架构边界

### 1.1 核心体验闭环
用户提出表格处理需求，模型生成真实标准 VBA，宿主插件忠实执行或如实拒绝拦截；过程默认保持一句话简洁汇报，可展开查看写后读回与审计细节；宏执行前自动对目标工作簿进行整本物理全量备份，用户可随时一键恢复到执行前版本；执行成功的自动化宏可一键命名保存入库，免 API Key 离线高频复用。

### 1.2 架构与技术边界
- **当前执行架构**：Windows 桌面版 Microsoft Excel（自适应 x64 / x86）。C# 宿主通过 COM Interop 原生接口（`VBComponents.Add(vbext_ct_StdModule)`）注入执行宏。
- **严禁概念混同**：严禁把历史 Office.js / Web Add-in 能力混同为当前桌面 VBA 真实执行能力；所有表格读写、宏运行与工作簿快照均由本地 C# 宿主与 Excel COM 直接驱动。
- **存储路径权威基准**：
  - **宏库持久化**：`%APPDATA%\ExcelMindAI\Scripts\`（保存 `.bas` 源码与 `.meta.json` 描述文件；自动向下兼容迁移旧目录 `%APPDATA%\LeeExcel\Scripts\`。注：历史个别报告中出现的 `ExcelMind\scripts` 为书写笔误，在此正式统一核实并修正为 `%APPDATA%\ExcelMindAI\Scripts\`，旧数据已由代码自动迁移完整可见；未经授权绝不迁移、重置或删除任何用户数据）。
  - **快照备份库**：`%APPDATA%\ExcelMindAI\Backups\<workbook_hash>\`（保存工作簿独立副本 `.xlsx`/`.xlsm` 与 `snapshots.json`；自动向下兼容迁移旧目录 `%APPDATA%\LeeExcel\Backups\`）。
  - **大模型配置**：WebView2 本地 LocalStorage（键名 `excelmind_ai_llm_config`，向下兼容迁移 `lee_excel_llm_config`），API Key 纯本地存储，绝不上报或中转。
  - **会话聊天记录**：当前完全处于前端 Svelte 运行时内存生命周期，单次会话有效，刷新或关闭窗格即重置；按真实实现标记为已知限制，R1a 严格不顺手实现历史持久化。

## 2. 不可退化的产品原则（铁律）

1. **不静默改写模型或用户 VBA**：绝不通过替换引号、正则替换变量、篡改算法、强改工作簿引用或删除 `Option Explicit` 等声明来掩盖错误；必须保持源码 100% 保真。
2. **宿主包装器与源码严格分离**：模型原始生成的 VBA、宿主执行包装器、导出模块属性与执行证据分别独立记录，透明展示。
3. **模型自由生成与快捷工具并列**：自由生成路径忠实呈现模型输出，快捷工具（如对账、去重）显式标为独立功能，绝不拿硬编码模板伪称“大模型智能生成”。
4. **用户显式选定通道为唯一模式来源**：CHAT（问答）与 AUTOMATION（操作）严格隔离。对话中提及或展示的代码绝不因为渲染而执行；无代码的纯文本回复绝不误报“宏执行失败”。
5. **不靠增加提示词禁令解决宿主缺陷**：禁止在全局提示词中堆砌“严禁逐格”、“限制35行”等负向偏置词；必要运行契约和不支持项显式向用户透明展示。
6. **不设隐藏输出预算，不静默删除历史**：不擅自强加隐藏截断，上下文裁剪必须可审计，用户保存的宏库与运行记录永久保留。
7. **快照是工作簿版本恢复，不是任意沙箱**：快照仅保障目标工作簿本身的物理回退，不能承诺撤销外部文件删除、网络请求或系统级副作用。
8. **客观核验，不伪称满分**：`UsedRange` 不等于本次修改区域；宏运行成功仅代表 COM 未抛出异常，不等于业务达成；主观排版如实标为“效果待确认”。
9. **绝对安全底线**：不删除用户 Profile，不修改系统 Excel 宏安全信任设置，绝不擅自触碰、移动或覆盖用户未授权的正式业务文件。
10. **小步迭代，证据驱动**：未经过真实 Excel 环境人工点击验收的，严禁标注为 `accepted`；严禁以内存模拟测试冒充真实宿主验证。

## 4. 阶段范围、不做项与依赖定义

### 4.1 R0：固定可用基线与规划治理 (当前阶段)
- **阶段范围**：
  - 核实现有代码真实能力，严格区隔“已实现”、“自动测试通过”、“用户人工验收”、“未验证”、“已知限制”；
  - 固化当前可用版本 v1.2.0 (Commit: `231ae3a`)，建立最小回归测试清单；
  - 建立唯一主规划 `docs/product-roadmap.md`，同步更新 `task_plan.md`、`progress.md`、`findings.md`；
  - 准备 R1a 最小切片接口与文件映射，交付后立即停下等待用户验收。
- **不做项 (Non-goals)**：
  - 严禁在此阶段编写任何 R1–R7 的业务功能代码；
  - 严禁删除或重构用户已验收的功能；
  - 严禁自动推送 Git 提交或合并分支。
- **依赖**：现有 Node 单测、PowerShell 脚本、Git 提交历史。
- **停点**：向用户提交 R0 审计报告与 R1a 接口设计方案，等待用户下发 R1a 启动指令。

### 4.2 R1：让 AI 看懂用户当前选区
- **阶段范围**：
  - **R1a（最小切片）**：用户在界面显式点击“附加选区”，宿主通过 COM 批量读取当前矩形区域的 Value2 与 Formula，前端展示包含工作簿名、工作表、地址、行列数、表头预览、前几行数据样本的只读卡片；用户勾选确认后再随 Prompt 发送。*(状态: `accepted`，用户人工实测通过)*
  - **交互缺陷专项修复 (BUG-FOCUS-01)**：修复 Excel 工作表与 WebView2 任务窗格输入焦点交接缺陷（点击文本框打字后再点击单元格，击键仍单向锁定在插件文本框）。采用轻量 WinForms 消息过滤与 COM 事件双层平滑交接，绝不使用模拟按键与全局操作系统钩子。*(状态: `accepted`，用户人工实测通过，焦点缺陷正式关闭；其他未实测边界保留待验)*
  - **R1b（可靠上下文与透明审计）**：选区过大时的智能抽样策略、Token 预算透明化展示、上一份引用宏只读展示、采集时间戳与旧快照提示、实际发送历史与裁剪可见可审计。*(状态: `planned`，已完成最小架构设计，严禁在此阶段编码，等待用户明确授权启动)*
- **不做项**：
  - 不自动全量静默上传整个工作簿数据；
  - 不逐格跨 COM 读取单元格（必须使用批量二维数组）；
  - 不强行用大模型推断或猜测业务表头语义；
  - 多选区（Union）、整列全选（如 A:A）必须友好降级或提示限制，不造成 Excel 界面假死。
- **依赖**：C# COM `Excel.Range.Value2` 批量读取、`NativeBridge` 新增 `get_selection_context`、`TaskPaneFocusHelper` Win32 焦点平滑交接。
- **停点**：R1a 与焦点缺陷已完成人工验收（`accepted`），当前停点在 R1b 启动前，等待用户明确下发 R1b 启动指令。

### 4.3 R2：宏库从保存升级为高频复用
- **阶段范围**：
  - **R2a**：宏库支持模糊搜索、分类标签、收藏置顶；运行历史详细绑定 `scriptId + versionId + sourceHash + targetIdentity + snapshotId`；提供恢复对应快照入口。
  - **R2b**：Excel Ribbon 动态菜单展示收藏宏，点击先提示入口函数与目标工作簿，不盲目替换原脚本中的固定引用。
  - **R2c**：显式参数化宏支持（仅针对用户主动声明 Typed 参数的脚本，如 Range/Sheet/Date/Number），通过独立元数据与宿主参数适配器传递。
- **不做项**：
  - 不使用 `eval` 执行任何参数；
  - 不用正则强行将任意旧 VBA 改写为参数化脚本；
  - 宏备份失败时绝对中止执行。
- **依赖**：`ScriptManager.cs` 元数据结构扩充、Ribbon 动态 XML 刷新。
- **停点**：用户在多工作簿场景下实测参数化宏调用与快照回滚。

### 4.4 R3：高频数据清洗与对账快捷工具
- **阶段范围**：
  - **R3a**：按键去重工具。用户显式选择区域与主键列，在 C# 内存中完成哈希比对，支持标记重复行或提取唯一样本。
  - **R3b**：两表主键对账工具。用户指定两表及其关联主键（单列或复合键），严格保持 19 位纯数字编码、前导零、工单号文本格式；在独立新 Sheet 中输出对账结果（唯一匹配、仅左表存在、仅右表存在、差异字段比对），默认绝不覆盖源表。
- **不做项**：
  - 严禁在自由生成聊天流中伪造为“大模型生成的宏”；必须明确标注为“快捷数据工具”；
  - 不搞未经用户确认的“模糊聚类合并”；
  - 不逐格循环比对（必须全量批量载入内存哈希处理）。
- **依赖**：C# 内存高效哈希字典算法、C# 批量写入 Range。
- **停点**：使用包含前导零（如 `001234`）、19 位身份证号/工单号、空键、中文表头的两张真实表格完成人工对账验收。

### 4.5 R4：批量文件任务引擎
- **阶段范围**：
  - **R4a**：用户选择多个 Excel 文件与一个固定版本的入库宏，后台以单 Excel 实例串行方式逐个打开副本、试运行并另存至新输出目录；任务面板实时展示每个文件的进度、状态、耗时与错误。
  - **R4b**：多文件列名对齐汇总工具，自动对齐不同工作簿中的同名列，追加“来源文件”与“来源工作表”两列。
- **不做项**：
  - 绝不并行跨线程调用同一个 Excel COM 实例；
  - 绝不默认覆盖原始文件（强制输出到独立目录）；
  - 绝不强杀用户已打开的 Excel 进程。
- **依赖**：批量任务调度队列、ClosedXML（仅限离线只读或新结果生成评估）。
- **停点**：混合 20 个正常文件、1 个只读文件、1 个损坏文件的批处理容错与取消人工验收。

### 4.6 R5：可复用工作流与报表
- **阶段范围**：
  - **R5a**：将“清洗 → 对账 → 汇总”两个以上步骤保存为有版本的任务流水线，记录每一步调用的宏版本与输入输出映射；执行前建立任务级整本快照。
  - **R5b**：汇总报表与图表生成，优先支持模型原生标准 VBA 代码生成，可选配预设报表模板。
- **不做项**：
  - 不搞通用的庞大拖拽低代码平台；
  - 不承诺跨多文件的分布式事务原子回滚。
- **依赖**：工作流配置持久化模型、多步骤状态机。
- **停点**：电信告警或销售日报从明细到图表的流水线端到端验证。

### 4.7 R6：数据接入与分发交付
- **阶段范围**：
  - **R6a**：支持只读 HTTP GET / CSV / JSON 数据拉取并写入表格；连接参数与 Token 存放在独立安全存储中，绝不混入 VBA 代码；
  - **R6b**：无凭据宏包导入/导出（`.exmpack` 或规范 zip），包含 manifest、VBA 源码与 SHA256 校验码，不含 API Key、用户聊天与业务数据；
  - **R6c**：环境自适应无损安装、升级检测与脱敏诊断日志导出。
- **不做项**：
  - 默认不支持 POST/DELETE 等带危险副作用的外部请求；
  - 导入宏包绝不自动执行。
- **依赖**：C# HttpClient 安全客户端、包结构序列化。
- **停点**：跨机器导入宏包并在离线环境下成功执行验收。

### 4.8 R7：远期高级计算引擎探索 (独立 PoC 选项)
- **探索内容**：
  - DuckDB Excel extension 针对超大规模（100万行+）多表 SQL 聚合的性能 PoC；
  - xlwings / Python 脚本作为高级科学计算外挂扩展；
  - Rubberduck 风格 ANTLR4 语法解析器进行 VBA 入口与变量静态只读诊断。
- **铁律约束**：仅作独立研究与技术储备，绝不强加为基础用户的运行依赖。

## 7. 最小回归清单 (Minimum Regression Checklist)

在任何阶段进行代码提交前，必须通过以下 8 项核心回归门禁，严禁发生破坏性退化：

1. **对话不执行**：在 CHAT 模式下，无论用户提出何种要求（即便包含“生成宏”、“画表格”），仅返回纯文本/代码块，绝对不调用 COM 宏执行器，不触发快照创建。
2. **操作写值**：在 AUTOMATION 模式下，有效 VBA 必须能成功在目标工作簿写入数据，且写后读回 `WorkbookReadback` 能够如实捕获修改后的单元格抽样、行列数与区域地址。
3. **无代码回复不伪报宏失败**：在 AUTOMATION 模式下，若模型仅返回解释性纯文本或拒绝执行说明（无代码块），前端界面友好展示文本内容，执行卡为 NULL，绝对不弹出“宏执行失败”红牌。
4. **导入保存重开**：通过“导入”功能粘贴或读取 `.bas` 文件保存入库后，关闭并重启 Excel 插件，宏库列表必须完整列出该脚本，元数据与源码 100% 保持一致。
5. **源码保真**：用户导入或模型生成的 VBA 宏源码，其单双引号、`Option Explicit`、中文注释、模块属性及算法逻辑 100% 原样持久化，绝对不在保存或执行时进行正则静默改写。
6. **运行错误展示**：当宏出现编译错误或运行时异常时，宿主必须准确捕获并展示错误触发阶段（`failureStage`）、VBA 错误码与描述、COM HResult，并将工作簿状态与已修改情况透明告知用户。
7. **快照恢复**：宏执行前必须在 `%APPDATA%\ExcelMindAI\Backups\` 成功建立目标工作簿独立物理副本；用户点击“一键恢复”时，能够安全替换回原状态，并在恢复前建立救援备份。
8. **冷启动无重复注册**：Excel-DNA 加载项在冷启动加载时，内部所有类中的非 Excel 函数收敛为 `internal`，绝对不在 Excel 函数向导中产生重复注册或覆盖报错。

## 8. 下一阶段 R1a 接口规格与实施映射预备

> **本节仅作为 R1a 的设计与文件映射预备，严格遵守 R0 范围，当前未编写具体实现代码。**

### 8.1 目标与用户交互流程
1. 用户在 Excel 中选定某个单元格区域（如 `A1:F20`）；
2. 用户在任务窗格输入框上方看到【📎 附加当前选区】按钮，点击后触发宿主读取；
3. 前端展示一个紧凑的只读卡片：
   - 工作簿名：`销售日报_2026.xlsx`
   - 工作表名：`Sheet1`
   - 选区地址：`$A$1:$F$20`（20 行 × 6 列）
   - 表头候选：`[站点ID, 日期, 告警级别, 频段, 吞吐量, 状态]`
   - 数据样本：首行数据 `[SITE001, 2026-10-01, Critical, 3.5GHz, 128.5, 正常]`
   - 选项勾选：`[x] 包含表头` `[x] 包含前3行样本` `[ ] 仅包含行列结构（不含数值）`
4. 用户输入自然语言提示词（如“按告警级别统计数量并生成柱状图”），点击发送；
5. 系统将选区元数据格式化为 Markdown 表格结构，作为上下文只读参数注入请求体，模型能够精确感知用户所在的具体表格范围与列名，无需再盲目使用 `UsedRange`。

### 8.2 接口与数据契约映射
- **前端发起动作**：
  ```json
  {
    "action": "get_selection_context",
    "requestId": "req_sel_123456",
    "params": {
      "sampleRowCount": 3
    }
  }
  ```
- **宿主返回响应 (`SelectionContextDto`)**：
  ```json
  {
    "ok": true,
    "action": "get_selection_context",
    "requestId": "req_sel_123456",
    "data": {
      "workbookName": "销售日报_2026.xlsx",
      "sheetName": "Sheet1",
      "address": "$A$1:$F$20",
      "rowCount": 20,
      "columnCount": 6,
      "isSingleArea": true,
      "headers": ["站点ID", "日期", "告警级别", "频段", "吞吐量", "状态"],
      "sampleRows": [
        ["SITE001", "2026-10-01", "Critical", "3.5GHz", "128.5", "正常"],
        ["SITE002", "2026-10-01", "Major", "2.6GHz", "96.2", "正常"]
      ],
      "hasFormulas": false,
      "hasMergedCells": false,
      "isFilteredOrHidden": false,
      "truncated": false
    }
  }
  ```

### 8.3 涉及文件映射
- **C# 宿主层**：
  - `src/NativeBridge.cs`：在 `Dispatch` 中增加 `case "get_selection_context"` 路由处理，提取 `app.Selection` 并调用提取方法；
  - `src/VbaRunner.cs`：实现 `GetSelectionContext(dynamic app, int sampleRows)` 辅助方法，使用 `range.Value2` 批量读取到二维 object 数组，严禁逐格 COM 遍历；多选区（Areas > 1）返回降级标识。
- **前端组件层**：
  - `web/src/services/bridge.ts`：增加 `getSelectionContext(sampleRows?: number)` 封装；
  - `web/src/components/ChatInput.svelte`：增加“附加选区”按钮与选区预览折叠条，支持移除与选项切换；
  - `web/src/services/llm.ts`：增加 `formatSelectionContextForPrompt(ctx)`，将上下文组装为带安全围栏的文本段。
